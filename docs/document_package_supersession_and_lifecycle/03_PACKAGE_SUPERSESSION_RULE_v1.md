# 03 PACKAGE SUPERSESSION RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for superseding documentation packages without losing readable continuity
Rule: package supersession must remain explicit so replacement strengthens documentation trust instead of fragmenting it

---

## 1. Purpose

This document defines the package-supersession rule of the platform.

It exists to preserve:
- readable replacement logic
- lower ambiguity around what package has been replaced
- continuity between old and new package meaning
- a stable base for later supersession hardening

---

## 2. Supersession Principle

Package supersession should remain understandable in terms of:
- what package replaced what
- what meaning moved forward
- what meaning remains historical only
- how supersession avoids interpretive confusion

---

## 3. Required Rule

Package supersession should remain:
- explicit
- readable
- continuity-aware
- governance-aware
- canon-preserving

---

## 4. What Is Forbidden

The following remain forbidden:
- package replacement with no readable predecessor relation
- superseded packages silently acting as current meaning
- replacement logic guessed only from recency
- supersession records preserved only in memory

---

## 5. Final Rule

A mature documentation system replaces packages through readable supersession, not through quiet abandonment.

---

## 6. Status

This document is the active canonical package-supersession rule until replaced by a stricter supersession reference.
