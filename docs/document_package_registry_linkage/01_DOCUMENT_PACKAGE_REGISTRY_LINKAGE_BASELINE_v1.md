# 01 DOCUMENT PACKAGE REGISTRY LINKAGE BASELINE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: baseline rules for linking package-manifest thinking with the central document registry
Rule: package manifests and the document registry must remain explicitly linked so package meaning and registry meaning do not drift apart

---

## 1. Purpose

This document defines the document-package-registry-linkage baseline of the platform.

It exists to preserve:
- alignment between package manifests and registry entries
- lower risk of package/registry drift
- machine-readable continuity between package and registry layers
- a stable base for future self-reading documentation behavior

---

## 2. Linkage Principle

Package-registry linkage should remain understandable in terms of:
- what package exists
- how that package appears in the registry
- what metadata should remain aligned
- what linkage fields must remain readable
- how package and registry interpretation reinforce each other

A package should not say one thing while the registry says another.

---

## 3. Required Rule

Package-registry linkage should remain:
- explicit
- machine-readable
- alignment-oriented
- canonical-first
- consistent with document meta-governance

---

## 4. What Is Forbidden

The following remain forbidden:
- package manifests drifting away from registry entries
- registry coverage that ignores package meaning
- duplicated metadata with conflicting semantics
- treating package and registry layers as unrelated systems

---

## 5. Final Rule

A mature documentation system links package meaning and registry meaning before scale introduces contradiction.

---

## 6. Status

This document is the active canonical document-package-registry-linkage baseline until replaced by a stricter package-registry linkage reference.
