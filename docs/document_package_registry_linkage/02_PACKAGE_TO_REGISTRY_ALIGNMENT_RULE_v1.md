# 02 PACKAGE TO REGISTRY ALIGNMENT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: alignment rule from package definitions into registry representation
Rule: package meaning must be reflected into the registry in a readable and non-contradictory form

---

## 1. Purpose

This document defines the package-to-registry alignment rule of the platform.

It exists to preserve:
- readable package reflection into the registry
- lower ambiguity across documentation navigation
- continuity between package identity and registry identity
- a stable base for later linkage hardening

---

## 2. Alignment Principle

Package-to-registry alignment should remain understandable in terms of:
- package identity
- package path
- package status
- package authority meaning
- package dependency and downstream usage meaning

---

## 3. Required Rule

Package-to-registry alignment should remain:
- explicit
- selective
- machine-readable
- stable
- non-contradictory

---

## 4. What Is Forbidden

The following remain forbidden:
- package identity that is not reflected in the registry
- registry entries that contradict package meaning
- alignment by guesswork only
- metadata duplication with no consistency discipline

---

## 5. Final Rule

A mature registry reflects package meaning deliberately, not approximately.

---

## 6. Status

This document is the active canonical package-to-registry alignment rule until replaced by a stricter alignment reference.
