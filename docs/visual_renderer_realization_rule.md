# VISUAL RENDERER REALIZATION RULE v1

Status: active renderer-realization rule
Scope: transition from first-picture contract milestone to renderer-facing realization layer
Rule: renderer-facing realization may prepare actual visual rendering paths, but may not bypass truth, policy, or read-only boundaries

---

## 1. Purpose

This document defines the rule for the first renderer-facing realization layer.

It exists to prevent:
- uncontrolled jump from first-picture contract milestone into ad-hoc renderer behavior
- renderer-owned truth
- hidden runtime shortcuts around canonical visual contracts

---

## 2. What Is Already True

At this stage, the project has reached:

- premium demo materialized output
- premium demo first picture

This means the first contract-first picture milestone is closed.

---

## 3. What the Renderer Realization Layer Is

The renderer realization layer is:

- downstream
- truth-bound
- read-only
- renderer-facing
- realization-oriented

The renderer realization layer is not:

- execution authority
- shell-owned truth
- runtime mutation path
- uncontrolled rendering shortcut

---

## 4. What Is Allowed

Renderer realization layers may:

- define renderer-facing readiness
- define render-safe visual packaging
- define first renderer-oriented visual state
- define future screen-output handoff boundaries

---

## 5. What Is Forbidden

The following remain forbidden:

- direct execution through renderer layer
- hidden mutation paths
- fake output synthesis
- renderer shortcuts that skip canonical chain
- shell-owned truth

---

## 6. Final Rule

A renderer realization layer may prepare actual rendering paths,
but it may not weaken the truth-preserving chain that precedes it.

---

## 7. Status

This document is the active rule for the first renderer-facing realization layer until replaced by a stricter rendered-view standard.
