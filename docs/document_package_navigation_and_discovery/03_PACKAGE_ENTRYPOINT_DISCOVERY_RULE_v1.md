# 03 PACKAGE ENTRYPOINT DISCOVERY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for discovering the right entrypoint into a documentation package
Rule: package entrypoints must remain discoverable so readers can start from the correct overview or law surface instead of entering the package at random

---

## 1. Purpose

This document defines the package-entrypoint-discovery rule of the platform.

It exists to preserve:
- readable package entrypoints
- lower ambiguity around where reading should begin
- continuity between package structure and package onboarding
- a stable base for later navigation hardening

---

## 2. Entrypoint Principle

Package entrypoint discovery should remain understandable in terms of:
- what file should be read first
- why that file is the entrypoint
- how entrypoint choice preserves orientation
- how discovery preserves documentation trust

---

## 3. Required Rule

Package entrypoint discovery should remain:
- explicit
- readable
- selective
- meaningful
- non-random

---

## 4. What Is Forbidden

The following remain forbidden:
- entering packages through random files by default
- package entrypoints guessed only from habit
- entrypoint logic preserved only in operator memory
- multiple competing entrypoints with no readable guidance

---

## 5. Final Rule

A mature documentation system makes package entrypoints readable before scale turns first contact into confusion.

---

## 6. Status

This document is the active canonical package-entrypoint-discovery rule until replaced by a stricter entry reference.
