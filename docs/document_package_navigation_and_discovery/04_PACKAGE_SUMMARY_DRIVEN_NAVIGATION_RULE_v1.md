# 04 PACKAGE SUMMARY DRIVEN NAVIGATION RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for using structured summaries to guide package navigation
Rule: package summaries must remain usable as navigation guides so readers can orient before deep reading begins

---

## 1. Purpose

This document defines the package-summary-driven-navigation rule of the platform.

It exists to preserve:
- readable summary-driven orientation
- lower ambiguity around package purpose and state
- continuity between package overview and package entry
- a stable base for later navigation hardening

---

## 2. Summary Principle

Summary-driven navigation should remain understandable in terms of:
- what the summary tells the reader first
- how the summary guides next reading steps
- what summary signals matter most
- how summary-guided navigation preserves trust

---

## 3. Required Rule

Summary-driven navigation should remain:
- explicit
- readable
- compact
- meaningful
- non-chaotic

---

## 4. What Is Forbidden

The following remain forbidden:
- package summaries too vague to guide navigation
- navigation that ignores summary signals entirely
- summary use preserved only in operator memory
- summary-driven guidance replaced by folder guessing

---

## 5. Final Rule

A mature documentation system uses package summaries to reduce navigation cost before deeper reading starts.

---

## 6. Status

This document is the active canonical package-summary-driven-navigation rule until replaced by a stricter navigation reference.
