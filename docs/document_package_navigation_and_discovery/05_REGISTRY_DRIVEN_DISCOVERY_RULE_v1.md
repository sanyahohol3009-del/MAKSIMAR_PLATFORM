# 05 REGISTRY DRIVEN DISCOVERY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for using the central document registry as a discovery surface for packages
Rule: package discovery must remain registry-driven where possible so navigation relies on readable metadata rather than directory memory or accidental familiarity

---

## 1. Purpose

This document defines the registry-driven-discovery rule of the platform.

It exists to preserve:
- readable metadata-driven discovery
- lower ambiguity around package finding
- continuity between package registry and package use
- a stable base for later navigation hardening

---

## 2. Registry Principle

Registry-driven discovery should remain understandable in terms of:
- what registry fields guide discovery
- how the registry narrows package search
- how registry-driven discovery preserves documentation trust
- how discovery avoids silent drift

---

## 3. Required Rule

Registry-driven discovery should remain:
- explicit
- machine-readable
- metadata-aware
- non-contradictory
- canon-preserving

---

## 4. What Is Forbidden

The following remain forbidden:
- package discovery detached from registry metadata
- silent return to folder-memory navigation
- registry discovery logic preserved only in operator memory
- package finding based on coincidence instead of declared structure

---

## 5. Final Rule

A mature documentation system uses registry-backed discovery before scale turns package search into manual archaeology.

---

## 6. Status

This document is the active canonical registry-driven-discovery rule until replaced by a stricter discovery reference.
