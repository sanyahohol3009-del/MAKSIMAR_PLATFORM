# 06 REGISTRY AND SUMMARY CONTEXT ALIGNMENT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for keeping minimum package context aligned with registry and summary layers
Rule: minimum package context must remain aligned with registry and summary surfaces so recovered package meaning does not drift away from declared metadata and summary meaning

---

## 1. Purpose

This document defines the registry-and-summary-context-alignment rule of the platform.

It exists to preserve:
- readable cross-layer context orientation
- lower ambiguity across context, registry, and summary layers
- continuity between recovered package meaning and declared package signals
- a stable base for later context hardening

---

## 2. Alignment Principle

Registry and summary context alignment should remain understandable in terms of:
- what context signals align with registry meaning
- what summary fields support minimum context
- how alignment preserves trust
- how interpretive drift is avoided

---

## 3. Required Rule

Registry and summary context alignment should remain:
- explicit
- readable
- non-contradictory
- alignment-aware
- incrementally hardenable

---

## 4. What Is Forbidden

The following remain forbidden:
- context signals conflicting with registry or summary meaning
- silent drift between recovered context and machine-readable layers
- alignment guessed only from memory
- context claims with no cross-layer discipline

---

## 5. Final Rule

A mature documentation system keeps minimum context aligned with registry and summary layers because safe continuation depends on that stability.

---

## 6. Status

This document is the active canonical registry-and-summary-context-alignment rule until replaced by a stricter alignment reference.
