# 05 MINIMUM OPEN GAPS CONTEXT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for preserving minimum open-gaps context across sessions and handoff points
Rule: minimum open-gaps context must remain readable so unfinished work can resume deliberately instead of being rediscovered after every pause

---

## 1. Purpose

This document defines the minimum-open-gaps-context rule of the platform.

It exists to preserve:
- readable unfinished-work recovery
- lower ambiguity around what still remains
- continuity between package closure and next work
- a stable base for later context hardening

---

## 2. Gaps Principle

Minimum open-gaps context should remain understandable in terms of:
- what remains incomplete
- what kind of future work is still expected
- what is blocked versus merely pending
- how gap context preserves continuity

---

## 3. Required Rule

Minimum open-gaps context should remain:
- explicit
- selective
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- unfinished work rediscovered only by rereading
- gap context overloaded with weak or irrelevant details
- open-gaps meaning preserved only in operator memory
- context that hides what still remains

---

## 5. Final Rule

A mature documentation system preserves open-gaps context clearly before pauses turn pending work into drift.

---

## 6. Status

This document is the active canonical minimum-open-gaps-context rule until replaced by a stricter context reference.
