# 01 DOCUMENT PACKAGE MINIMUM VIABLE CONTEXT BASELINE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: baseline rules for minimum viable context across documentation packages
Rule: documentation packages must expose minimum viable context so humans and future JARVIS can recover essential package meaning without reconstructing the entire package from scratch

---

## 1. Purpose

This document defines the document-package-minimum-viable-context baseline of the platform.

It exists to preserve:
- readable minimum package context
- lower recovery cost across sessions
- continuity between package structure and essential interpretation
- a stable base for later context hardening

---

## 2. Context Principle

Package minimum viable context should remain understandable in terms of:
- what the package is
- what state it is in now
- what remains unfinished
- what minimum context must survive for safe continuation

Minimum viable context should preserve orientation without requiring full package rereading.

---

## 3. Required Rule

Package minimum viable context should remain:
- explicit
- package-aware
- human-readable
- canonical-first
- incrementally hardenable

---

## 4. What Is Forbidden

The following remain forbidden:
- package recovery dependent on full rereading by default
- essential package meaning preserved only in operator memory
- context signals too vague to support real continuation
- context growth that creates noise instead of clarity

---

## 5. Final Rule

A mature documentation system preserves minimum viable context before scale turns continuation into repeated reconstruction.

---

## 6. Status

This document is the active canonical document-package-minimum-viable-context baseline until replaced by a stricter context reference.
