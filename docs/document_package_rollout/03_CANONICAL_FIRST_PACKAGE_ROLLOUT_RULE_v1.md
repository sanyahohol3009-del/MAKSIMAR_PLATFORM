# 03 CANONICAL FIRST PACKAGE ROLLOUT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: canonical-first ordering during package-manifest rollout
Rule: manifest rollout must begin with the most canonical packages so future JARVIS and human readers gain structure where interpretive risk is highest

---

## 1. Purpose

This document defines the canonical-first-package-rollout rule of the platform.

It exists to preserve:
- first coverage for highest-authority packages
- lower risk of structured metadata arriving late where it matters most
- clearer interpretive hierarchy during rollout
- a stable base for future package-manifest scaling

---

## 2. Canonical-First Principle

Canonical-first rollout should remain understandable in terms of:
- which packages shape interpretation most strongly
- which packages future layers depend on first
- which packages deserve structured manifest treatment before others
- how rollout protects interpretive clarity

---

## 3. Required Rule

Canonical-first package rollout should remain:
- explicit
- authority-aware
- priority-aware
- readable
- consistent with document meta-governance

---

## 4. What Is Forbidden

The following remain forbidden:
- rolling out low-value historical packages first
- delaying canonical package structure behind convenience work
- flattening package priority during rollout
- treating all packages as equally urgent

---

## 5. Final Rule

A mature documentation system structures its strongest packages before its easiest ones.

---

## 6. Status

This document is the active canonical canonical-first-package-rollout rule until replaced by a stricter package rollout reference.
