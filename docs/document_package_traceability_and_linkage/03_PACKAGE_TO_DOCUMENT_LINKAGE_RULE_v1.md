# 03 PACKAGE TO DOCUMENT LINKAGE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for tracing package meaning to its constituent documents
Rule: package-to-document linkage must remain readable so package meaning can be verified through the documents that actually define it

---

## 1. Purpose

This document defines the package-to-document-linkage rule of the platform.

It exists to preserve:
- readable linkage from package to documents
- lower ambiguity around where package meaning comes from
- continuity between package identity and document evidence
- a stable base for later linkage hardening

---

## 2. Linkage Principle

Package-to-document linkage should remain understandable in terms of:
- what documents belong to the package
- what documents are primary
- what documents are supportive
- how package meaning can be verified through them

---

## 3. Required Rule

Package-to-document linkage should remain:
- explicit
- selective
- meaningful
- machine-readable
- non-decorative

---

## 4. What Is Forbidden

The following remain forbidden:
- package meaning with no readable document trail
- decorative document linkage with no interpretive value
- package membership guessed only from folder browsing
- document linkage logic preserved only in operator memory

---

## 5. Final Rule

A mature documentation system links package meaning to the documents that actually carry it.

---

## 6. Status

This document is the active canonical package-to-document-linkage rule until replaced by a stricter linkage reference.
