# 02 MACHINE READABILITY SCOPE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: scope rule for how machine readability should be interpreted across documentation packages
Rule: machine readability scope must remain explicit so structured package interpretation stays bounded, meaningful, and readable

---

## 1. Purpose

This document defines the machine-readability-scope rule of the platform.

It exists to preserve:
- bounded machine-readable interpretation
- lower ambiguity around what structure is intentionally machine-readable
- continuity between package role and structured metadata
- a stable base for later machine-readability hardening

---

## 2. Scope Principle

Machine readability scope should remain understandable in terms of:
- what fields are intentionally structured
- what remains human-oriented prose
- what remains out of scope for now
- how machine readability differs across package families

---

## 3. Required Rule

Machine readability scope should remain:
- explicit
- bounded
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- undefined machine-readable boundaries
- packages treated as fully structured without readable justification
- structure growth with no boundary discipline
- scope ambiguity preserved only in operator memory

---

## 5. Final Rule

A mature machine-readability layer first defines what machines may reliably interpret before it relies on that interpretation.

---

## 6. Status

This document is the active canonical machine-readability-scope rule until replaced by a stricter scope reference.
