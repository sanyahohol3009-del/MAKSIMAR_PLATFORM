# 02 INTERPRETATION SCOPE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: scope rule for how package interpretation should be bounded across documentation layers
Rule: interpretation scope must remain explicit so package meaning stays bounded, readable, and justified

---

## 1. Purpose

This document defines the interpretation-scope rule of the platform.

It exists to preserve:
- bounded package interpretation
- lower ambiguity around package applicability
- continuity between package role and package interpretation
- a stable base for later interpretation hardening

---

## 2. Scope Principle

Interpretation scope should remain understandable in terms of:
- what package meaning applies now
- what package meaning is contextual only
- what remains outside justified interpretation
- how interpretation differs across package families

---

## 3. Required Rule

Interpretation scope should remain:
- explicit
- bounded
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- undefined interpretation scope
- packages treated as universally applicable by default
- interpretation growth with no readable boundary
- scope ambiguity preserved only in operator memory

---

## 5. Final Rule

A mature interpretation layer first defines where package meaning applies before it relies on that meaning.

---

## 6. Status

This document is the active canonical interpretation-scope rule until replaced by a stricter scope reference.
