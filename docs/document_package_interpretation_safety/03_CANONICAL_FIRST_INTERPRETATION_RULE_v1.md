# 03 CANONICAL FIRST INTERPRETATION RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for canonical-first interpretation of documentation packages
Rule: canonical package meaning must remain the first interpretation layer so weaker package classes do not silently redefine current platform law

---

## 1. Purpose

This document defines the canonical-first-interpretation rule of the platform.

It exists to preserve:
- readable primacy of canonical material
- lower risk of interpretation drift
- continuity between active law and package usage
- a stable base for later interpretation hardening

---

## 2. Canonical Principle

Canonical-first interpretation should remain understandable in terms of:
- what canonical packages define
- what weaker layers may clarify without overriding
- how interpretive drift is avoided
- how documentation trust is preserved

---

## 3. Required Rule

Canonical-first interpretation should remain:
- explicit
- stable
- readable
- canon-preserving
- governance-aware

---

## 4. What Is Forbidden

The following remain forbidden:
- weaker package layers silently redefining canonical meaning
- closure or history treated as stronger than law
- interpretation order inferred only by habit
- canonical primacy preserved only in memory

---

## 5. Final Rule

A mature documentation system keeps interpretation anchored in canon before it consults weaker layers.

---

## 6. Status

This document is the active canonical canonical-first-interpretation rule until replaced by a stricter precedence reference.
