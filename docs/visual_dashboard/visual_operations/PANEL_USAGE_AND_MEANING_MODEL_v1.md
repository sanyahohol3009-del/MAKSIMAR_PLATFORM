# PANEL USAGE AND MEANING MODEL v1

Status: active canonical panel usage/meaning model
Scope: how operators should understand and use panels as meaningful system surfaces
Rule: panel usage must remain structured enough that panels support understanding rather than becoming arbitrary visual fragments

---

## 1. Purpose

This document defines the panel usage and meaning model of the platform.

It exists to preserve clarity about:
- how panels are used
- what kind of system meaning panels should surface
- why operator-facing panel usage must remain more structured than casual screen browsing

---

## 2. Usage Principle

Panels should support operator understanding of things such as:
- runtime condition
- health or degraded state
- diagnostics or incident context
- status overview
- future domain-specific visibility where appropriate

Panels are not merely boxes on a screen.
They are semantic visibility surfaces.

---

## 3. Required Rule

Panel usage should remain explainable in terms of:
- what the panel represents
- what upstream meaning it depends on
- what operator question it helps answer
- what it does not imply in terms of authority or control

---

## 4. What Is Forbidden

The following remain forbidden:
- panel usage by visual habit alone
- panels with no stable semantic role
- operator dependence on layout intuition without semantic structure
- panel meaning drifting away from actual system interpretation

---

## 5. Final Rule

Panels are useful when they answer operator questions with structured meaning, not when they merely occupy space.

---

## 6. Status

This document is the active canonical panel usage/meaning model until replaced by a stricter panel-operations reference.
