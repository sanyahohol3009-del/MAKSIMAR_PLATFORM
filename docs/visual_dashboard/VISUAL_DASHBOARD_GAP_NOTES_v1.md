# VISUAL DASHBOARD GAP NOTES v1

Status: active canonical visual/dashboard gap notes
Scope: limitations of the current visual/dashboard baseline pass
Rule: the visual/dashboard pass must remain explicit about what is still baseline-level or incomplete

---

## 1. Purpose

This document records the current limitations of the visual/dashboard baseline pass.

It exists to keep the pass honest and bounded.

---

## 2. Current Gap Notes

### Gap 1
The current pass establishes a baseline, not yet a full renderer, visual shell, or panel registry specification family.

### Gap 2
The pass does not yet replace detailed display topology or visual composition runbooks.

### Gap 3
Per-panel and per-view implementation mappings are still future work.

### Gap 4
Future deeper documentation is still needed for:
- panel registry normalization
- display placement logic
- workspace/layout families
- renderer and visual realization families
- tighter linkage to observability and runtime-facing views

---

## 3. Required Rule

These notes do not invalidate the baseline.
They show where later hardening is still needed.

---

## 4. Final Rule

A visual/dashboard baseline may begin high-level if its incompleteness is explicit.

---

## 5. Status

This document is the active canonical visual/dashboard gap note set until replaced by a stricter visual/dashboard audit.
