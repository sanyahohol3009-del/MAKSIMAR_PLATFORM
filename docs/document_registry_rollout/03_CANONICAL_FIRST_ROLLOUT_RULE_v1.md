# 03 CANONICAL FIRST ROLLOUT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for prioritizing active canonical material during registry rollout
Rule: registry rollout must prioritize active canonical documentation first so the registry strengthens platform truth before it catalogs everything else

---

## 1. Purpose

This document defines the canonical-first rollout rule of the platform.

It exists to preserve:
- truth-first registry growth
- lower risk of historical noise dominating the registry
- stronger machine-readable prioritization
- a stable base for later audit and history coverage

---

## 2. Canonical-First Principle

Registry rollout should first capture:
- active canonical package families
- documents with the highest interpretation weight
- documents that govern later operational meaning
- documents that future JARVIS must read before lower-priority material

---

## 3. Required Rule

Canonical-first rollout should remain:
- explicit
- priority-aware
- truth-oriented
- non-random
- consistent with interpretation-priority semantics

---

## 4. What Is Forbidden

The following remain forbidden:
- indexing historical notes before core law
- flattening canonical and non-canonical material into equal priority
- treating audit closure as more urgent than governing documents
- registry growth that weakens authority clarity

---

## 5. Final Rule

A mature registry records what governs the platform before it records everything that ever happened to it.

---

## 6. Status

This document is the active canonical canonical-first-rollout rule until replaced by a stricter registry-priority reference.
