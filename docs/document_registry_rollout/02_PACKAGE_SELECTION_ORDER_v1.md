# 02 PACKAGE SELECTION ORDER v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: ordering logic for which documentation packages enter the registry next
Rule: package selection order must remain deliberate so the registry grows by interpretive value rather than by accident

---

## 1. Purpose

This document defines the package-selection-order baseline of the platform.

It exists to preserve:
- value-based registry expansion
- lower ambiguity about what gets indexed next
- continuity between document importance and rollout order
- a stable base for future broader registry normalization

---

## 2. Selection Principle

Package rollout order should remain understandable in terms of:
- canonical importance
- interpretive centrality
- active platform relevance
- dependency value for future readers
- practical feasibility of entry creation

---

## 3. Current Preferred Order

Preferred next registry coverage should prioritize:
- active canonical packages
- meta-governance packages
- high-value platform law families
- major operational contract families
- audit layers later, not first

---

## 4. What Is Forbidden

The following remain forbidden:
- indexing low-value historical material before core canonical packages
- random rollout order
- letting convenience override interpretive importance
- treating every package as equally urgent

---

## 5. Final Rule

A mature registry expands by interpretive priority, not by folder roulette.

---

## 6. Status

This document is the active canonical package-selection-order reference until replaced by a stricter rollout-order standard.
