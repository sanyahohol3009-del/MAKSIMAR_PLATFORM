# 06 USED BY CAPTURE DISCIPLINE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: practical discipline for capturing used_by metadata during registry rollout
Rule: downstream usage metadata must remain readable so future humans and JARVIS can see why a package matters beyond its own folder

---

## 1. Purpose

This document defines the used_by-capture discipline of the platform.

It exists to preserve:
- readable downstream relevance
- lower ambiguity about future usage
- stronger machine-readable navigation
- a stable base for later linkage growth

---

## 2. Capture Principle

The used_by field should remain understandable in terms of:
- what future package, workflow, or capability depends on this package
- what later reading path this document enables
- what downstream value justifies registry inclusion

---

## 3. Required Rule

Used_by capture should remain:
- explicit
- practical
- future-facing
- non-bloated
- useful for navigation

---

## 4. What Is Forbidden

The following remain forbidden:
- empty downstream semantics forever
- random or inflated used_by lists
- pretending a package has no downstream meaning when it clearly enables later work
- turning used_by into speculative noise

---

## 5. Final Rule

A mature registry shows not only what a package is, but what later work stands on it.

---

## 6. Status

This document is the active canonical used_by-capture discipline until replaced by a stricter downstream linkage reference.
