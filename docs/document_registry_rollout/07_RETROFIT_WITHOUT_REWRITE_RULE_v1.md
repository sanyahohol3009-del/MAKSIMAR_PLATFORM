# 07 RETROFIT WITHOUT REWRITE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for widening registry coverage without forcing mass document rewrites
Rule: registry rollout must support incremental retrofit so documentation governance improves without stalling platform progress

---

## 1. Purpose

This document defines the retrofit-without-rewrite rule of the platform.

It exists to preserve:
- practical governance improvement
- lower risk of documentation paralysis
- compatibility with already-established document families
- a stable base for future normalization work

---

## 2. Retrofit Principle

Registry retrofit should remain understandable in terms of:
- adding coverage without rewriting everything at once
- improving discoverability before perfect normalization
- accepting phased metadata improvement
- preserving forward motion

---

## 3. Required Rule

Retrofit without rewrite should remain:
- explicit
- incremental
- non-destructive
- governance-improving
- compatible with future normalization

---

## 4. What Is Forbidden

The following remain forbidden:
- insisting on full rewrite before useful registry expansion
- blocking rollout on total perfection
- throwing away older useful documents because they are not yet normalized
- replacing practical progress with documentation paralysis

---

## 5. Final Rule

A mature documentation system improves structure in phases instead of demanding total rewrite before any gain is allowed.

---

## 6. Status

This document is the active canonical retrofit-without-rewrite rule until replaced by a stricter normalization policy.
