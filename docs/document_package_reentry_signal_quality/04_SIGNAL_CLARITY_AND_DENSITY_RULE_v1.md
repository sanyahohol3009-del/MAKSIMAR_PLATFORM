# 04 SIGNAL CLARITY AND DENSITY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for keeping reentry signals clear and appropriately dense across documentation packages
Rule: reentry signals must remain clear and density-bounded so restart cues stay usable instead of collapsing into clutter

---

## 1. Purpose

This document defines the signal-clarity-and-density rule of the platform.

It exists to preserve:
- readable signal structure
- lower risk of over-dense reentry cues
- continuity between signal richness and restart usability
- a stable base for later signal hardening

---

## 2. Clarity Principle

Signal clarity and density should remain understandable in terms of:
- what makes a signal clear
- when density becomes harmful
- what level of detail is sufficient
- how clarity preserves restart trust

---

## 3. Required Rule

Signal clarity and density should remain:
- explicit
- selective
- meaningful
- readable
- non-chaotic

---

## 4. What Is Forbidden

The following remain forbidden:
- dense reentry signals that hide priority
- signal expansion that destroys readability
- clarity logic preserved only in operator memory
- pretending more detail always improves restart quality

---

## 5. Final Rule

A mature documentation system protects signal clarity before restart cues become overloaded.

---

## 6. Status

This document is the active canonical signal-clarity-and-density rule until replaced by a stricter clarity reference.
