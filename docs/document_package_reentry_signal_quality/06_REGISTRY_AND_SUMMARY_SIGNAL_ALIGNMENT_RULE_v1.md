# 06 REGISTRY AND SUMMARY SIGNAL ALIGNMENT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for keeping reentry signals aligned with registry and summary layers
Rule: reentry signals must remain aligned with registry and summary surfaces so restart cues do not drift away from declared metadata and summary meaning

---

## 1. Purpose

This document defines the registry-and-summary-signal-alignment rule of the platform.

It exists to preserve:
- readable cross-layer signal orientation
- lower ambiguity across restart cues, registry, and summary layers
- continuity between recovered package meaning and declared package signals
- a stable base for later signal hardening

---

## 2. Alignment Principle

Registry and summary signal alignment should remain understandable in terms of:
- what signals align with registry meaning
- what summary fields support reentry cues
- how alignment preserves trust
- how interpretive drift is avoided

---

## 3. Required Rule

Registry and summary signal alignment should remain:
- explicit
- readable
- non-contradictory
- alignment-aware
- incrementally hardenable

---

## 4. What Is Forbidden

The following remain forbidden:
- reentry signals conflicting with registry or summary meaning
- silent drift between restart cues and machine-readable layers
- alignment guessed only from memory
- signal claims with no cross-layer discipline

---

## 5. Final Rule

A mature documentation system keeps reentry signals aligned with registry and summary layers because reliable restart depends on that stability.

---

## 6. Status

This document is the active canonical registry-and-summary-signal-alignment rule until replaced by a stricter alignment reference.
