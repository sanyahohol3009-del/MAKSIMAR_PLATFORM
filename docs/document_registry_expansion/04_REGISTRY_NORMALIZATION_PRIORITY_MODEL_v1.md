# 04 REGISTRY NORMALIZATION PRIORITY MODEL v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: priority model for which document families should be normalized into the registry first
Rule: normalization priority must remain explicit so registry retrofit work increases clarity instead of consuming energy indiscriminately

---

## 1. Purpose

This document defines the registry-normalization-priority model of the platform.

It exists to preserve:
- higher-value normalization first
- lower ambiguity around retrofit order
- reduced documentation sprawl risk
- a stable base for broader registry adoption

---

## 2. Priority Principle

Normalization priority should remain understandable in terms of:

### Highest priority
- active canonical packages
- constitutional documentation
- packages used by future codegen or self-reading logic

### Medium priority
- audit closure packages
- implementation-facing packages
- validation and runbook families

### Later priority
- continuity-history packages
- older reference families
- legacy material needing later cleanup

---

## 3. Required Rule

Normalization priority should remain:
- explicit
- value-oriented
- governance-aware
- machine-readability aware
- compatible with platform momentum

---

## 4. What Is Forbidden

The following remain forbidden:
- treating all documents as equal normalization urgency
- spending early energy on lowest-priority material first
- ignoring constitutional material while normalizing incidental history
- retrofit order decided only by convenience

---

## 5. Final Rule

A mature registry normalizes the most authoritative and most reusable documentation first.

---

## 6. Status

This document is the active canonical registry-normalization-priority model until replaced by a stricter registry retrofit priority reference.
