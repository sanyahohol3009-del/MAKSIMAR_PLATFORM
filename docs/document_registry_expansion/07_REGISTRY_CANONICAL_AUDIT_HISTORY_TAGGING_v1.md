# 07 REGISTRY CANONICAL AUDIT HISTORY TAGGING v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: tagging rules separating canonical, audit-closure, and continuity-history material inside the registry
Rule: registry tagging must preserve interpretive separation so future JARVIS does not confuse law, closure, and history

---

## 1. Purpose

This document defines the registry-canonical-audit-history tagging rule of the platform.

It exists to preserve:
- interpretive separation across document classes
- lower risk of authority confusion
- clearer machine-readable document weighting
- a stable base for larger registry coverage

---

## 2. Tagging Principle

Registry tagging should make clear whether a package is primarily:
- canonical
- audit_closure
- continuity_history

These are not interchangeable categories.

---

## 3. Required Rule

Registry tagging should remain:
- explicit
- authority-aware
- interpretation-aware
- machine-readable
- consistent with document meta-governance

---

## 4. What Is Forbidden

The following remain forbidden:
- mixing law and historical memory under the same interpretation weight
- treating audit closure as equivalent to constitutional law
- leaving package class to filename inference only
- registry growth with flattened authority semantics

---

## 5. Final Rule

A mature registry preserves category boundaries before it scales interpretation.

---

## 6. Status

This document is the active canonical registry-canonical-audit-history tagging rule until replaced by a stricter registry classification reference.
