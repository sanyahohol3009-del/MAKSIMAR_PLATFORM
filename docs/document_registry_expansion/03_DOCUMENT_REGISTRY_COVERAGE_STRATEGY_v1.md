# 03 DOCUMENT REGISTRY COVERAGE STRATEGY v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: strategy for widening registry coverage without blocking platform progress
Rule: registry coverage should expand in a pragmatic order so documentation governance improves without forcing full retroactive normalization in one pass

---

## 1. Purpose

This document defines the document-registry-coverage strategy of the platform.

It exists to preserve:
- practical registry growth
- canonical-first prioritization
- lower retrofit friction
- a stable base for staged documentation normalization

---

## 2. Coverage Principle

Registry coverage should expand in a readable order:

1. new meta-governance families
2. active canonical families
3. audit-closure families
4. continuity and historical families
5. legacy or older families requiring later normalization

---

## 3. Required Rule

Coverage strategy should remain:
- incremental
- canonical-first
- audit-aware
- historical-aware
- compatible with ongoing platform work

---

## 4. What Is Forbidden

The following remain forbidden:
- demanding full historical retrofit before any useful progress
- prioritizing low-authority history over active canonical law
- expanding registry in arbitrary folder order only
- turning registry work into a freeze on platform development

---

## 5. Final Rule

A mature registry expands by interpretive priority, not by random file order.

---

## 6. Status

This document is the active canonical document-registry-coverage strategy until replaced by a stricter registry rollout reference.
