# 03 UPSTREAM PACKAGE REFERENCE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for how upstream package references should be recorded and interpreted
Rule: upstream package references must remain readable so package meaning can be traced back to the law, contract, or baseline it stands on

---

## 1. Purpose

This document defines the upstream-package-reference rule of the platform.

It exists to preserve:
- readable upstream meaning
- lower ambiguity around prior package authority
- continuity between package use and package foundations
- a stable base for later graph hardening

---

## 2. Upstream Principle

Upstream package reference should remain understandable in terms of:
- what package frames the current one
- what should be read first
- what upstream meaning remains interpretively important
- how upstream reference preserves documentation trust

---

## 3. Required Rule

Upstream package reference should remain:
- explicit
- selective
- meaningful
- graph-aware
- machine-readable

---

## 4. What Is Forbidden

The following remain forbidden:
- upstream meaning left implicit
- decorative upstream references with no interpretive value
- random accumulation of references
- upstream logic preserved only in operator memory

---

## 5. Final Rule

A mature documentation graph records what a package stands on before asking others to stand on it.

---

## 6. Status

This document is the active canonical upstream-package-reference rule until replaced by a stricter graph reference.
