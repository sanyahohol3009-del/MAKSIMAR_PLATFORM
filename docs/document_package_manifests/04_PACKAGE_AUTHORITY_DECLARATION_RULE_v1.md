# 04 PACKAGE AUTHORITY DECLARATION RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: declaration of package-level authority meaning in documentation manifests
Rule: package authority must remain explicit so future JARVIS and human readers do not treat all documentation packages as interpretively equal

---

## 1. Purpose

This document defines the package-authority-declaration rule of the platform.

It exists to preserve:
- readable authority at package level
- lower confusion between law, contract, audit, and history packages
- better machine interpretation of package importance
- a stable base for future self-reading behavior

---

## 2. Authority Principle

Package authority declaration should remain understandable in terms of:
- whether the package is mainly canonical, operational, audit-oriented, or historical
- how strongly it should shape interpretation
- whether it creates rules or records closure
- what kind of downstream use is legitimate

---

## 3. Required Rule

Package authority declaration should remain:
- explicit
- stable
- interpretable
- package-level
- consistent with document meta-governance

---

## 4. What Is Forbidden

The following remain forbidden:
- packages with no readable authority role
- treating all packages as equally normative
- mixing strong canonical meaning with historical meaning invisibly
- forcing future readers to reconstruct authority package-by-package from raw text only

---

## 5. Final Rule

A mature documentation system explains package authority before asking others to depend on it.

---

## 6. Status

This document is the active canonical package-authority-declaration rule until replaced by a stricter package-authority reference.
