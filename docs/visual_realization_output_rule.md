# VISUAL REALIZATION OUTPUT RULE v1

Status: active realization-output rule
Scope: transition from realization artifact layer to first output-facing realization path
Rule: output realization layers may prepare materialized output delivery, but may not bypass truth, policy, or read-only boundaries

---

## 1. Purpose

This document defines the rule for the realization-output layer.

It exists to prevent:
- uncontrolled jump from realization artifact into ad-hoc output rendering
- fake output paths outside canonical visual chain
- hidden renderer/runtime ownership of visual truth

---

## 2. What Is Already True

At this stage, the project has reached:

- premium demo picture boundary
- premium demo picture ready
- premium demo realization artifact

This means the project has crossed from picture contour into artifact-facing realization state.

---

## 3. What the Realization Output Layer Is

The realization output layer is:

- downstream
- truth-bound
- read-only
- output-facing
- realization-preparatory

The realization output layer is not:

- execution authority
- shell-owned truth
- runtime mutation path
- uncontrolled renderer shortcut

---

## 4. What Is Allowed

Realization output layers may:

- define output-facing realization readiness
- define delivery-safe output state
- define output packaging boundaries
- define first honest output realization path

---

## 5. What Is Forbidden

The following remain forbidden:

- direct execution through output layer
- hidden mutation paths
- fake rendered output
- renderer shortcuts that skip canonical contracts
- shell-owned truth

---

## 6. Final Rule

A realization output layer may prepare output delivery,
but it may not weaken the truth-preserving chain that precedes it.

---

## 7. Status

This document is the active rule for the realization-output layer until replaced by a stricter rendered-output standard.
