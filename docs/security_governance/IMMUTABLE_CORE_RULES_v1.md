# IMMUTABLE CORE RULES v1

Status: active canonical immutable-core rule
Scope: protected and non-casual-change platform foundations
Rule: the platform must preserve the concept of an immutable or highly protected core so fundamental safety and governance assumptions are not casually rewritten

---

## 1. Purpose

This document defines the current immutable-core principle of the platform.

It exists to prevent:
- casual redefinition of foundational safety logic
- upward write drift into protected areas
- convenience changes that silently weaken core invariants

---

## 2. Immutable-Core Principle

The project recognizes the need for a protected foundational layer whose role is to anchor:
- platform invariants
- governance discipline
- core legitimacy rules
- safety-sensitive assumptions

This does not necessarily mean “nothing can ever change.”
It means changes to protected foundations must be exceptional, explicit, and governed.

---

## 3. Required Rule

Protected or immutable-core behavior must not be treated like ordinary feature code.

If foundational rules are changed, that change must be:
- explicit
- documented
- validated
- governed
- not introduced through accidental drift

---

## 4. What Is Forbidden

The following remain forbidden:
- silent mutation of protected assumptions
- informal rewriting of core safety/governance behavior
- treating convenience as sufficient justification for core change
- hidden write paths into protected foundations

---

## 5. Final Rule

A platform with serious safety ambitions requires a protected foundation, not only fast iteration.

---

## 6. Status

This document is the active canonical immutable-core rule until replaced by a stricter immutable/protected foundation standard.
