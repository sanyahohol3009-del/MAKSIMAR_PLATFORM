# PROPOSAL TO ACTION TRANSITION v1

Status: active canonical proposal-to-action transition rule
Scope: transition from suggestion or simulation to real action
Rule: the transition from proposal to action must remain explicit, reviewable, and governed

---

## 1. Purpose

This document defines the transition logic from proposal to action.

It exists to prevent:
- proposal being mistaken for approval
- simulation being mistaken for execution
- silent transitions into side effects
- loss of human legitimacy in action paths

---

## 2. Transition Principle

The platform should preserve distinct states such as:
- proposal
- sandbox or simulation
- report or diff
- review
- explicit approval
- real action

These are different legitimacy stages.

---

## 3. Required Rule

A proposal must not become real action unless the legitimacy transition is explicit.

At minimum, the transition should remain:
- visible
- understandable
- deliberate
- governed

---

## 4. What Is Forbidden

The following remain forbidden:
- proposal automatically becoming apply
- simulation automatically becoming deployment
- review UI standing in for explicit approval
- ambiguous handoff from suggestion to execution

---

## 5. Final Rule

A safe system preserves a visible boundary between “could do” and “will do.”

---

## 6. Status

This document is the active canonical proposal-to-action transition rule until replaced by a stricter action-transition specification.
