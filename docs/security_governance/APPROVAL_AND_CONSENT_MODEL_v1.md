# APPROVAL AND CONSENT MODEL v1

Status: active canonical approval/consent model
Scope: human approval, consent-first behavior, and governed action legitimacy
Rule: the platform may reason broadly, but meaningful write/apply/action behavior must remain subject to explicit approval and consent discipline

---

## 1. Purpose

This document defines the current approval and consent model of the platform.

It exists to prevent:
- unapproved action execution
- silent write/apply behavior
- “helpful” automation that bypasses user authority
- unsafe transition from reasoning to action

---

## 2. Consent-First Principle

The platform should distinguish between:
- reasoning
- proposing
- simulating
- reporting
- applying changes or actions

Reasoning and proposal may be broad.
Apply/write/action legitimacy must remain governed.

---

## 3. Approval Rule

Meaningful action should require explicit approval when it crosses important boundaries such as:
- file mutation
- runtime-affecting changes
- protected configuration changes
- external action dispatch
- future agent/swarm execution with side effects

---

## 4. Required Rule

The platform must not blur:
- suggestion
- simulation
- implementation
- approval
- real action

These are different states of legitimacy.

---

## 5. What Is Forbidden

The following remain forbidden:
- silent apply behavior
- consent bypass through UI convenience
- implicit approval by ambiguity
- hidden write paths triggered by reasoning-only flows

---

## 6. Final Rule

The platform may think freely.
It must not act freely.

---

## 7. Status

This document is the active canonical approval/consent model until replaced by a stricter governed-action specification.
