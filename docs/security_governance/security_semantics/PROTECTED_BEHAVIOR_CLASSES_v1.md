# PROTECTED BEHAVIOR CLASSES v1

Status: active canonical protected-behavior class baseline
Scope: categories of behavior requiring stronger governance or protection
Rule: the platform should recognize that some classes of behavior are more sensitive and must remain more strongly governed

---

## 1. Purpose

This document defines baseline protected behavior classes in the platform.

It exists to preserve the idea that not all actions are equal in legitimacy risk.

---

## 2. Protected Behavior Classes

Examples of behavior classes that require stronger governance include:
- write/apply behavior
- runtime-affecting modification
- changes to protected configuration
- authority-shifting behavior
- external dispatch or integration with side effects
- future autonomous multi-agent actions with real effect

---

## 3. Required Rule

Protected behavior classes must not be treated as ordinary low-risk interactions.

They require stronger legitimacy, clearer boundaries, and better explainability.

---

## 4. What Is Forbidden

The following remain forbidden:
- treating sensitive write/apply behavior as casual convenience
- hiding protected behavior behind ambiguous UI language
- implicitly escalating low-risk interactions into high-risk behavior

---

## 5. Final Rule

Behavior sensitivity must remain explicit if governance is to remain meaningful.

---

## 6. Status

This document is the active canonical protected-behavior class baseline until replaced by a stricter behavior-class governance reference.
