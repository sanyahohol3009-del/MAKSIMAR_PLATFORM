# AGENT ROLE AND CAPABILITY MODEL v1

Status: active canonical agent role/capability model
Scope: how agent roles and capabilities should be understood across the platform
Rule: agent roles and capabilities must remain explicit so multi-agent growth does not collapse into ambiguous authority or undefined behavior

---

## 1. Purpose

This document defines the current agent role and capability model of the platform.

It exists to preserve clarity about:
- what an agent role is
- why capabilities must be bounded
- how role meaning differs from authority
- why explicit capability modeling is part of multi-agent discipline

---

## 2. Role Principle

An agent role should remain understandable in terms of:
- what it is for
- what it may handle
- what it must not silently assume
- how it relates to other roles

A role is not equivalent to unlimited execution power.

---

## 3. Capability Principle

Capabilities should remain:
- explicit
- bounded
- explainable
- subordinate to governance and approval discipline
- distinct from platform legitimacy itself

Different roles may have different capability profiles.
These profiles are not identical in authority.

---

## 4. Required Rule

Agent role and capability interpretation should remain explainable in terms of:
- role purpose
- allowed capability surface
- limits and boundaries
- relation to governed action and approval requirements

---

## 5. What Is Forbidden

The following remain forbidden:
- agent roles with no defined capability meaning
- capability claims detached from governance
- treating role labels as sufficient justification for action
- multi-agent complexity hiding authority inflation

---

## 6. Final Rule

Roles and capabilities make multi-agent systems safer when they remain explicit and bounded.

---

## 7. Status

This document is the active canonical agent role/capability model until replaced by a stricter agent-capability reference.
