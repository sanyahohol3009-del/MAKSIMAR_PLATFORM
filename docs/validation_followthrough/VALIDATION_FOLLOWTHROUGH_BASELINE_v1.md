# VALIDATION FOLLOWTHROUGH BASELINE v1

Status: active canonical validation follow-through baseline
Scope: whole-platform validation discipline after baseline documentation establishment
Rule: validation must remain a lived operational discipline, not only a documented principle

---

## 1. Purpose

This document defines the current validation follow-through baseline of the platform.

It exists to preserve:
- continuity between written validation rules and actual practice
- whole-platform integrity checking
- reproducible validation behavior
- disciplined use of fast, layer, and full validation tiers

---

## 2. Baseline Principle

Validation is not complete merely because rules exist.

Validation follow-through means the platform should preserve:
- actual repeatable validation habits
- explicit full-platform checks
- clear distinction between fast and deep validation
- stable expectations for serial and parallel runs
- interpretable validation outcomes

---

## 3. Required Rule

The project must not drift into a state where:
- validation docs exist but are not operationally followed
- only partial checks are trusted forever
- full-platform validation disappears by convenience

---

## 4. What Is Forbidden

The following remain forbidden:
- treating validation as symbolic paperwork
- silently abandoning full-suite discipline
- confusing isolated green checks with whole-platform integrity
- letting speed erase correctness discipline

---

## 5. Final Rule

Validation must remain both documented and actually practiced.

---

## 6. Status

This document is the active canonical validation follow-through baseline until replaced by a stricter validation operations reference.
