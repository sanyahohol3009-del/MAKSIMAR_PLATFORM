---

## 1. Purpose

This document defines the package-registry-sync-repair runbook of the platform.

It exists to preserve:
- readable cross-layer correction
- lower sync ambiguity
- continuity across registry and package layers
- a stable base for later sync hardening

---

## 2. Repair Principle

Package/registry sync repair should remain understandable in terms of:
- what layer drifted
- what field no longer aligns
- what should be corrected first
- how repair restores stable cross-layer meaning

---

## 3. Required Rule

Package/registry sync repair should remain:
- explicit
- stable
- readable
- non-contradictory
- machine-readable

---

## 4. What Is Forbidden

The following remain forbidden:
- sync repair by guesswork
- contradictory package and registry meaning left unresolved
- unstable alignment normalized as acceptable
- repair that introduces new cross-layer ambiguity

---

## 5. Final Rule

A mature documentation system repairs package/registry drift before cross-layer meaning becomes unreliable.
