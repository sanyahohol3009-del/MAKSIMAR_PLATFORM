---

## 1. Purpose

This document defines the sync-dependency-mismatch runbook of the platform.

It exists to preserve:
- readable dependency correction
- lower graph ambiguity
- continuity between dependency claims and actual cross-layer meaning
- a stable base for later graph hardening

---

## 2. Repair Principle

Dependency sync repair should remain understandable in terms of:
- what dependency is weak or wrong
- whether it remains meaningful across layers
- what should be corrected first
- how repair restores real interpretive value

---

## 3. Required Rule

Dependency sync repair should remain:
- explicit
- selective
- meaningful
- graph-aware
- machine-readable

---

## 4. What Is Forbidden

The following remain forbidden:
- random dependency mismatch left unrepaired
- dependency fields drifting into appearance-only metadata
- oversized dependency lists accepted without correction
- graph claims with no interpretive value

---

## 5. Final Rule

A mature documentation graph repairs sync dependency meaning before graph density weakens trust.
