# DOCUMENTATION REQUIREMENTS MATRIX v1

Status: active canonical documentation requirement rule
Scope: project-wide documentation obligation
Rule: every major architectural, runtime, validation, safety, and integration layer must be represented by explicit documentation

---

## 1. Purpose

This document defines documentation as a mandatory project feature.

It exists to prevent:
- undocumented architecture
- undocumented operational rules
- undocumented validation behavior
- loss of continuity across chats, operators, or implementation phases
- silent governance drift

---

## 2. Required Documentation Families

The project should maintain documentation for:
- architecture
- contracts and boundaries
- security and governance
- validation and testing
- runtime health and observability
- incidents and failure handling
- mobile/accelerator integration
- visual/dashboard rules
- future operator and deployment workflows
- platform-wide full test policy
- periodic validation schedule policy
- validation trigger and escalation policy

---

## 3. Required Principle

If a layer is important enough to build,
it is important enough to document.

If a rule is important enough to enforce,
it is important enough to write down.

If a behavior is important enough to trust,
it is important enough to verify and explain.

---

## 4. Documentation Roles

Documentation must serve as:
- architectural memory
- operator memory
- implementation boundary memory
- governance memory
- continuity memory
- validation memory

---

## 5. Required Rule

The project must not treat documentation as optional polish.

Documentation is required for:
- critical architectural layers
- boundary rules
- validation logic
- failure classification
- runtime governance
- major integration tracks
- recurring whole-platform testing discipline

---

## 6. What Is Forbidden

The following remain forbidden:
- “we will remember later”
- silent undocumented drift
- undocumented critical behavior
- treating documentation as optional polish
- relying only on chat memory for system-defining rules

---

## 7. Final Rule

Documentation is not decoration.
Documentation is part of the system.

---

## 8. Status

This document is the active canonical documentation requirement rule until replaced by a stricter project governance standard.
