# CANONICAL RUNBOOK REQUIREMENTS v1

Status: active canonical runbook requirements rule
Scope: operational and operator-facing procedures
Rule: any practical system area that may need operation, recovery, or diagnosis should eventually have a runbook

---

## 1. Purpose

This document defines runbook expectations for the project.

It exists to prevent:
- systems that are buildable but not operable
- recovery knowledge living only in chat memory
- repeated operator confusion during runtime issues

---

## 2. Runbook Targets

Runbooks should exist over time for:
- boot/start procedures
- shutdown/stop procedures
- testing procedures
- health inspection procedures
- incident diagnosis procedures
- rollback/recovery procedures
- future release procedures

---

## 3. Required Rule

If a subsystem can fail in practice or must be operated in practice, it should eventually gain a runbook.

---

## 4. Final Rule

Operational knowledge must be documented, not improvised every time.

---

## 5. Status

This document is the active canonical runbook requirements rule until replaced by a stricter operations documentation standard.
