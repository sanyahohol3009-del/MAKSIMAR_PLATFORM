# DOCUMENTATION LIFECYCLE RULE v1

Status: active canonical documentation lifecycle rule
Scope: creation, update, verification, and aging of documents
Rule: documentation must be created, maintained, reviewed, and corrected as part of the same lifecycle as the system it describes

---

## 1. Purpose

This document defines how documentation lives over time.

It exists to prevent:
- documents written once and forgotten
- code moving while documents stay stale
- continuity loss through outdated notes
- orphaned documentation with no relevance

---

## 2. Lifecycle Stages

Documentation should move through stages such as:
- created
- active
- updated
- verified
- outdated
- superseded
- archived

---

## 3. Required Rule

When a system layer changes materially, its documentation must be:
- reviewed
- updated if needed
- marked outdated if no longer valid
- superseded if replaced by a newer canonical document

---

## 4. Verification Principle

Documents should be periodically checked for:
- relevance
- consistency with current architecture
- missing updates
- conflict with newer canonical rules

---

## 5. Supersession Rule

A newer document may replace an older one only if:
- the replacement is explicit
- the new rule is clearer or stricter
- the continuity of meaning is preserved

---

## 6. What Is Forbidden

The following remain forbidden:
- stale documents presented as canonical
- replacing documents implicitly without notice
- silent supersession
- keeping invalid rules active by neglect

---

## 7. Final Rule

Documentation must evolve with the system, not trail behind it indefinitely.

---

## 8. Status

This document is the active canonical documentation lifecycle rule until replaced by a stricter documentation maintenance standard.
