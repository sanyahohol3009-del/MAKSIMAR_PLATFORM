# DOCUMENTATION MAP AND COVERAGE PASS v1

Status: active canonical documentation mapping pass
Scope: whole-project documentation coverage assessment
Rule: before further expansion, the project must map what is documented, partially documented, missing, outdated, or still inconsistent

---

## 1. Purpose

This document defines the documentation mapping pass for the whole project.

It exists to ensure that:
- documentation work becomes systematic
- missing critical documents are made visible
- project continuity no longer depends on scattered memory
- future implementation can proceed on top of a known documentation baseline

---

## 2. Current Mode

The project is currently in:

DOCUMENTATION HARDENING & CANONICALIZATION PASS v1

Meaning:
- feature expansion is paused
- new implementation layers are not the priority
- documentation coverage takes priority over expansion
- the project must establish a reliable documentation baseline

---

## 3. Required Mapping Categories

Every major project domain should be classified as one of:

- documented
- partially documented
- missing
- outdated
- conflicting
- not yet assessed

---

## 4. Required Domains

The documentation map must cover at least:

- core architecture
- security/governance
- runtime/operations
- validation/testing
- observability/diagnostics
- visual/dashboard
- mobile/bridge/accelerator
- AI/memory/self-awareness
- agent/swarm
- runbooks/operator procedures
- release/change discipline

---

## 5. Required Outputs

This pass should produce:
- a coverage matrix
- a gap register
- a remediation priority list
- a shared status legend

---

## 6. Hard Rule

The project must not resume broad feature expansion until foundational documentation gaps are visible and prioritized.

---

## 7. Final Rule

A large system must know what it has documented before it can claim continuity.

---

## 8. Status

This document is the active canonical documentation mapping pass until replaced by a stricter project documentation baseline standard.
