# DOCUMENTATION STATUS LEGEND v1

Status: active canonical status legend
Scope: documentation mapping and coverage interpretation
Rule: coverage language must remain explicit and stable across the project

---

## 1. Purpose

This document defines the allowed documentation status labels.

It exists to prevent:
- vague status language
- inconsistent interpretation of coverage
- false confidence

---

## 2. Allowed Status Labels

### documented
Meaning:
- domain has a meaningful canonical baseline
- coverage is materially present
- continuity is supported

### partially documented
Meaning:
- some meaningful documentation exists
- continuity is partly preserved
- more structured coverage is still required

### missing
Meaning:
- the documentation family is recognized as required
- but canonical coverage is materially absent

### outdated
Meaning:
- documentation exists
- but no longer reliably matches current reality

### conflicting
Meaning:
- multiple active documents or rules disagree materially

### not yet assessed
Meaning:
- domain has not yet been formally classified

---

## 3. Required Rule

These labels should be used consistently in:
- coverage matrices
- gap registers
- remediation plans
- future documentation audits

---

## 4. Final Rule

Stable status language is necessary for honest coverage reporting.

---

## 5. Status

This document is the active canonical status legend until replaced by a stricter coverage reporting standard.
