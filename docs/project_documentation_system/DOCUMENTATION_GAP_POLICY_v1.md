# DOCUMENTATION GAP POLICY v1

Status: active canonical documentation gap policy
Scope: missing, partial, outdated, or inconsistent documentation
Rule: documentation gaps must be identified, classified, and closed in a controlled order

---

## 1. Purpose

This document defines how the project handles documentation gaps.

It exists to prevent:
- endless undocumented expansion
- pretending gaps do not exist
- random patching of missing docs with no priority order

---

## 2. Canonical Gap Classes

Documentation may be:
- documented
- partially documented
- missing
- outdated
- conflicting
- superseded but not cleaned up

---

## 3. Priority Order

Documentation gaps should be closed in roughly this order:
1. core architecture
2. security/governance
3. runtime/operations
4. validation/testing
5. observability/incidents
6. visual/dashboard
7. mobile/bridge
8. advanced AI/self-awareness/swarm areas

---

## 4. Required Rule

The project should not continue indefinite expansion while critical documentation gaps remain in foundational layers.

---

## 5. Final Rule

Documentation gaps are technical debt.
They must be made visible and reduced intentionally.

---

## 6. Status

This document is the active canonical documentation gap policy until replaced by a stricter documentation debt standard.
