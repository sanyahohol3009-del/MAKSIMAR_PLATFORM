# REPOSITORY AWARE MAPPING BASELINE v1

Status: active canonical repository-aware mapping baseline
Scope: mapping documentation families to real repository structure
Rule: project documentation must become repository-aware so canonical meaning is tied to real project structure rather than only abstract discussion

---

## 1. Purpose

This document defines the repository-aware mapping baseline of the platform.

It exists to preserve:
- continuity between docs and repo structure
- lower drift between architecture language and real folders
- readable mapping from platform domains to implementation surfaces
- a stable base for deeper repo-aware documentation

---

## 2. Baseline Principle

Documentation should not remain only family-level and abstract.

It should increasingly become aware of:
- where major domains live
- which subtree carries which role
- how documentation families connect to repository structure
- where future deeper runbooks and mappings should attach

---

## 3. Mapping Intent

Repository-aware mapping should help answer:
- where a domain lives
- what subtree expresses that domain
- what that subtree is for
- what it must not silently redefine

---

## 4. Required Rule

Repository-aware mapping should remain:
- explicit
- structural
- readable
- bounded
- subordinate to canonical architecture and governance

---

## 5. What Is Forbidden

The following remain forbidden:
- documentation completely detached from repo layout
- subtree meaning known only from memory
- folder growth with no architectural mapping
- implementation drift hidden by abstract docs only

---

## 6. Final Rule

A mature project should be documentable not only by concepts, but also by real repository structure.

---

## 7. Status

This document is the active canonical repository-aware mapping baseline until replaced by a stricter repo-structure reference.
