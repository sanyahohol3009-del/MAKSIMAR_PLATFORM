# DISCOVERY AND HANDSHAKE BASELINE v1

Status: active canonical discovery/handshake baseline
Scope: discovery and legitimacy establishment for external accelerator attachment
Rule: discovery and handshake must remain explicit so external attachment is governed and explainable rather than implicit and fragile

---

## 1. Purpose

This document defines the discovery and handshake baseline of the platform.

It exists to preserve:
- readable device-discovery logic
- bounded legitimacy for external attachment
- structured transition into external mode
- a stable base for later discovery and handshake flow families

---

## 2. Discovery Principle

Discovery should remain understandable in terms of:
- whether an external candidate exists
- whether it can be identified
- whether it matches expected capability and protocol expectations
- whether it should be ignored when legitimacy is unclear

Discovery alone is not handshake success.

---

## 3. Handshake Principle

Handshake should remain understandable in terms of:
- capability confirmation
- protocol confirmation
- bounded trust establishment
- visible transition into external mode only when conditions are satisfied

Handshake is not a decorative step.
It is part of legitimacy.

---

## 4. Required Rule

Discovery and handshake thinking should remain:
- explicit
- bounded
- legitimacy-aware
- non-chaotic
- consistent with fallback and governance discipline

---

## 5. What Is Forbidden

The following remain forbidden:
- external mode entered without explicit handshake logic
- attachment legitimacy assumed from physical presence alone
- discovery and handshake collapsed into vague convenience behavior
- hidden transition into external mode with no structural explanation

---

## 6. Final Rule

A mature external-accelerator path must discover deliberately and attach legitimately.

---

## 7. Status

This document is the active canonical discovery/handshake baseline until replaced by a stricter attachment reference.
