# CORE PLATFORM ARCHITECTURE BASELINE v1

Status: active canonical core architecture baseline
Scope: whole-platform structural baseline
Rule: the project must preserve one coherent core architecture baseline describing the main domains and their relationship

---

## 1. Purpose

This document defines the current architectural baseline of MAKSIMAR/JARVIS at the core platform level.

It exists to preserve:
- structural continuity
- domain separation
- system-level understanding
- a stable baseline for future documentation passes

---

## 2. Core Platform Domains

The platform currently includes or plans for domains such as:

- core architecture and canonical contracts
- security / governance
- runtime / execution control
- observability / diagnostics
- validation / testing / CI-CD
- visual / dashboard / operator layer
- mobile / bridge / accelerator extensions
- AI / memory / self-awareness
- agent / swarm
- future physical AI / simulation extensions

---

## 3. Baseline Structural Principle

The platform is not one flat codebase.
It is a layered modular system with separated concerns.

The preferred separation is:

- canonical models / contracts / rules
- server/runtime behavior
- observability and diagnostics
- operator-facing visual layers
- external/mobile/accelerator extensions

---

## 4. Required Rule

The platform must remain understandable as one coherent architecture even when modules grow independently.

No new domain may invalidate the existence of the others as part of the same platform.

---

## 5. What Is Forbidden

The following remain forbidden:
- flat undifferentiated platform growth
- collapsing all domains into one execution blob
- undocumented redefinition of core architecture

---

## 6. Final Rule

The platform must preserve one stable architectural baseline even while expanding modularly.

---

## 7. Status

This document is the active canonical core architecture baseline until replaced by a stricter full-architecture reference.
