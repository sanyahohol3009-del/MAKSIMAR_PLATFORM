# CORE EXPANSION RULES v1

Status: active canonical expansion rule
Scope: how the platform may grow without damaging structural integrity
Rule: platform expansion must remain modular, documented, and subordinate to foundational structure

---

## 1. Purpose

This document defines rules for platform expansion at the core architecture level.

It exists to prevent:
- uncontrolled feature sprawl
- novelty-driven structural damage
- undocumented growth
- optional domains overtaking foundational discipline

---

## 2. Expansion Principle

Expansion is allowed,
but it must occur in ways that preserve:
- foundational structure
- boundary clarity
- upstream/downstream logic
- authority discipline
- documentation continuity

---

## 3. Required Rule

Before a new major domain or layer expands materially, the project should be able to explain:
- where the new domain sits
- what it depends on
- what it must not redefine
- how it will be documented
- how it will be validated

---

## 4. Forbidden Expansion Patterns

The following remain forbidden:
- expansion with no documentation trail
- expansion that collapses domain boundaries
- expansion that implicitly changes core legitimacy rules
- expansion that bypasses validation or structural discipline

---

## 5. Final Rule

The platform may grow widely, but it must not grow incoherently.

---

## 6. Status

This document is the active canonical expansion rule until replaced by a stricter architectural growth standard.
