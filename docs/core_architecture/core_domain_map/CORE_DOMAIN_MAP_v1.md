# CORE DOMAIN MAP v1

Status: active canonical core domain map
Scope: whole-platform core domain structure
Rule: the core platform must be understandable as a set of explicit domains rather than an undifferentiated system blob

---

## 1. Purpose

This document defines the current high-level map of core project domains.

It exists to preserve:
- domain visibility
- architectural orientation
- continuity across implementation phases
- a stable reference point for later domain-specific documentation

---

## 2. Core Domains

The project currently includes or plans for the following major domains:

- Core Contracts / Canonical Models
- Security / Governance
- Runtime / Execution Control
- Observability / Diagnostics
- Validation / Testing / CI-CD
- Visual / Dashboard / Operator Layer
- Mobile / Bridge / Accelerator
- AI / Memory / Self-Awareness
- Agent / Swarm
- Physical AI / Simulation / Future Robotics Extensions

---

## 3. Mapping Principle

These domains are not equal in role.

Some are foundational:
- core contracts
- security/governance
- runtime
- validation

Some are downstream or operator-facing:
- observability
- dashboard
- mobile surfaces

Some are strategic/future-facing:
- self-awareness
- swarm
- physical AI / simulation

---

## 4. Required Rule

Each domain must remain nameable, distinguishable, and documentable.

A domain may grow internally, but must not disappear into an undocumented merged mass.

---

## 5. Final Rule

A platform this large must be mapped by domains if it is to remain explainable.

---

## 6. Status

This document is the active canonical core domain map until replaced by a stricter whole-platform domain reference.
