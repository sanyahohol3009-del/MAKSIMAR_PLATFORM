# CORE DOMAIN RELATIONSHIPS v1

Status: active canonical domain relationship baseline
Scope: high-level relationships among core platform domains
Rule: major domains must be related explicitly so the platform remains structurally understandable

---

## 1. Purpose

This document defines the current high-level relationships between core domains.

It exists to prevent:
- vague architecture descriptions
- domain growth with no relationship map
- misunderstanding of upstream and downstream roles

---

## 2. Relationship Baseline

The current relationship logic is broadly:

- Core Contracts / Canonical Models support most other domains
- Security / Governance constrains runtime and future action paths
- Runtime / Execution Control carries live system behavior
- Observability / Diagnostics reads and interprets runtime/system signals
- Visual / Dashboard presents downstream state to the operator
- Mobile / Bridge / Accelerator extends access and backend modes
- Validation / Testing checks integrity across all of the above
- AI / Memory / Self-Awareness and Agent / Swarm grow on top of stable foundations
- Physical AI / Simulation layers remain future higher-order extensions

---

## 3. Upstream / Downstream Principle

The preferred logic is:
- truth and contracts stay upstream
- interpretation stays downstream
- presentation stays further downstream
- optional extensions do not redefine foundational truth

---

## 4. Required Rule

No downstream domain should silently replace the role of an upstream domain without explicit architectural revision.

---

## 5. Final Rule

The platform remains coherent when domain relationships remain visible.

---

## 6. Status

This document is the active canonical domain relationship baseline until replaced by a stricter system relationship map.
