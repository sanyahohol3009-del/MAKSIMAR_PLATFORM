# CORE FLOW TOPOLOGY v1

Status: active canonical flow-topology baseline
Scope: high-level flow orientation across core domains
Rule: platform flow must remain intelligible as a directed structure rather than an accidental mesh

---

## 1. Purpose

This document defines the current high-level flow topology of the platform.

It exists to prevent:
- accidental mesh growth
- unclear execution and interpretation order
- loss of flow explainability

---

## 2. High-Level Flow Logic

The current preferred flow orientation is broadly:

- canonical rules and contracts define allowed structure
- governance constrains what execution may do
- runtime/execution performs live behavior
- observability reads and interprets runtime/system state
- dashboard/presentation exposes downstream views
- external/mobile surfaces consume through explicit bridge logic
- future advanced domains build on top of stable lower layers

---

## 3. Flow Discipline

Important flow principles include:
- upstream defines
- runtime executes
- observability interprets
- dashboard presents
- extensions attach through explicit interfaces
- future intelligence layers must not silently redefine lower-layer truth

---

## 4. Required Rule

The project should remain explainable in terms of flow direction, not only file presence.

---

## 5. What Is Forbidden

The following remain forbidden:
- accidental circular architectural meaning
- hidden authority inversion
- presentation re-owning execution truth
- extensions bypassing foundational flow discipline

---

## 6. Final Rule

Flow clarity is part of platform stability.

---

## 7. Status

This document is the active canonical flow-topology baseline until replaced by a stricter flow architecture reference.
