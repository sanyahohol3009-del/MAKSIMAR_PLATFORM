# MEMORY AND PROVENANCE MODEL v1

Status: active canonical memory/provenance model
Scope: how memory and source origin should be understood across the platform
Rule: memory must remain structured and provenance-aware so continuity does not become fabricated confidence

---

## 1. Purpose

This document defines the current memory and provenance model of the platform.

It exists to preserve clarity about:
- what memory is for
- why provenance matters
- how remembered context differs from authoritative truth
- why continuity must remain source-aware

---

## 2. Memory Principle

Memory should support:
- continuity
- context preservation
- cross-step reasoning
- structured recall
- operator and project coherence over time

Memory should not automatically mean:
- perfect authority
- permanent truth
- unrestricted legitimacy

---

## 3. Provenance Principle

Provenance matters because remembered material may come from:
- canonical documentation
- runtime or diagnostics artifacts
- prior validated project decisions
- operator input
- bounded interpretation layers

These sources are not identical in authority.

---

## 4. Required Rule

Memory and provenance should remain explainable in terms of:
- what is remembered
- where it came from
- how authoritative it is
- what it may support
- what it may not replace

---

## 5. What Is Forbidden

The following remain forbidden:
- memory with no source awareness
- treating remembered context as automatically canonical truth
- continuity confidence detached from provenance
- fabricated authority through vague recall language

---

## 6. Final Rule

Memory is useful when it preserves continuity without pretending that all remembered things are equally authoritative.

---

## 7. Status

This document is the active canonical memory/provenance model until replaced by a stricter memory architecture reference.
