# 04 PACKAGE STATE AND GAPS SUMMARY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for summarizing package state and remaining gaps in a structured form
Rule: package state and open gaps must remain clearly summarized so package maturity can be understood without rereading the entire pass history

---

## 1. Purpose

This document defines the package-state-and-gaps-summary rule of the platform.

It exists to preserve:
- readable package maturity signals
- lower ambiguity around what is done versus unfinished
- continuity between package closure and future work
- a stable base for later summary hardening

---

## 2. State Principle

Package state and gaps summary should remain understandable in terms of:
- what is established
- what remains incomplete
- what kind of future work is still expected
- how summary preserves continuity

---

## 3. Required Rule

Package state and gaps summary should remain:
- explicit
- compact
- meaningful
- readable
- non-chaotic

---

## 4. What Is Forbidden

The following remain forbidden:
- packages with no readable maturity summary
- completion claims detached from remaining gaps
- gap understanding preserved only in operator memory
- summaries that blur established and unfinished work together

---

## 5. Final Rule

A mature documentation system summarizes package state and gaps before restart cost becomes too high.

---

## 6. Status

This document is the active canonical package-state-and-gaps-summary rule until replaced by a stricter summary reference.
