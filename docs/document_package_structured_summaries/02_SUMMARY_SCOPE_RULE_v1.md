# 02 SUMMARY SCOPE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: scope rule for how package summaries should be structured and interpreted
Rule: package summary scope must remain explicit so summaries stay bounded, meaningful, and readable

---

## 1. Purpose

This document defines the summary-scope rule of the platform.

It exists to preserve:
- bounded summary interpretation
- lower ambiguity around what summaries should include
- continuity between package role and package overview
- a stable base for later summary hardening

---

## 2. Scope Principle

Package summary scope should remain understandable in terms of:
- what package facts belong in the summary
- what remains for deeper documents
- what remains out of scope for now
- how summary scope differs across package families

---

## 3. Required Rule

Package summary scope should remain:
- explicit
- bounded
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- undefined summary boundaries
- summaries trying to replace the entire package
- summary growth with no readable discipline
- scope ambiguity preserved only in operator memory

---

## 5. Final Rule

A mature summary layer first defines what belongs in a package summary before it relies on that summary.

---

## 6. Status

This document is the active canonical summary-scope rule until replaced by a stricter scope reference.
