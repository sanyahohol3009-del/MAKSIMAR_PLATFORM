# 03 ACTIVE PACKAGE USAGE RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: rule for how active packages should be used in current interpretation
Rule: active packages must remain the primary source of current package guidance so present documentation meaning stays stable and readable

---

## 1. Purpose

This document defines the active-package-usage rule of the platform.

It exists to preserve:
- readable primacy of active packages
- lower risk of outdated override
- continuity between active meaning and current interpretation
- a stable base for later usage hardening

---

## 2. Active Principle

Active package usage should remain understandable in terms of:
- what active packages currently govern
- what they should be used for first
- how they relate to superseded and historical materials
- how current documentation trust is preserved

---

## 3. Required Rule

Active package usage should remain:
- explicit
- stable
- readable
- canon-preserving
- lifecycle-aware

---

## 4. What Is Forbidden

The following remain forbidden:
- current interpretation that bypasses active packages casually
- active meaning weakened by convenience use of older material
- current package use inferred only from habit
- active package primacy preserved only in memory

---

## 5. Final Rule

A mature documentation system keeps current guidance anchored in active packages.

---

## 6. Status

This document is the active canonical active-package-usage rule until replaced by a stricter usage reference.
