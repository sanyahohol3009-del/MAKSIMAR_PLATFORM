# 04 SUPERSEDED PACKAGE USAGE BOUNDARY v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: boundary rule for using superseded packages
Rule: superseded packages must remain usage-bounded so replaced material can stay readable without silently re-entering as current guidance

---

## 1. Purpose

This document defines the superseded-package-usage-boundary rule of the platform.

It exists to preserve:
- readable boundaries for replaced packages
- lower risk of superseded override
- continuity between current guidance and replaced context
- a stable base for later lifecycle hardening

---

## 2. Boundary Principle

Superseded package usage should remain understandable in terms of:
- what superseded packages may still explain
- what they no longer govern
- how they may support context without overriding active guidance
- how interpretive drift is avoided

---

## 3. Required Rule

Superseded package usage should remain:
- explicit
- bounded
- readable
- context-aware
- non-chaotic

---

## 4. What Is Forbidden

The following remain forbidden:
- superseded packages silently treated as current law
- replaced material overriding active package meaning
- superseded usage guessed from recency or memory alone
- boundary logic preserved only in operator memory

---

## 5. Final Rule

A mature documentation system keeps superseded packages contextual unless active layers explicitly require otherwise.

---

## 6. Status

This document is the active canonical superseded-package-usage-boundary rule until replaced by a stricter usage reference.
