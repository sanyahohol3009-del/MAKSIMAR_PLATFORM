# DISPLAY TOPOLOGY BASELINE v1

Status: active canonical display-topology baseline
Scope: how display surfaces and placement contexts should be understood across the dashboard layer
Rule: display topology must remain downstream of panel and workspace meaning so screen placement does not become hidden truth or control authority

---

## 1. Purpose

This document defines the display-topology baseline of the platform.

It exists to preserve clarity about:
- what display topology is for
- how displays differ from panels and workspaces
- why screen placement should remain subordinate to dashboard semantics

---

## 2. Display Topology Principle

Display topology may include:
- one or more display surfaces
- placement contexts
- future main, secondary, or role-based display arrangements
- future mobile or external visibility surfaces

Display topology expresses where visibility is shown, not what truth is.

---

## 3. Required Rule

Display topology interpretation should remain:
- explicit
- downstream
- distinct from panel identity
- distinct from workspace semantics
- non-authoritative over runtime and observability truth

---

## 4. What Is Forbidden

The following remain forbidden:
- monitor placement treated as semantic truth
- display count or location acting like platform authority
- screen arrangement silently redefining dashboard structure
- topology logic detached from panel and workspace meaning

---

## 5. Final Rule

A mature dashboard system separates what is shown from where it is shown.

---

## 6. Status

This document is the active canonical display-topology baseline until replaced by a stricter display-topology reference.
