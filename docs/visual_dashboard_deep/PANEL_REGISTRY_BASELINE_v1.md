# PANEL REGISTRY BASELINE v1

Status: active canonical panel-registry baseline
Scope: canonical registration and identity of dashboard panels
Rule: panels must remain registry-backed semantic entities rather than ad hoc screen fragments

---

## 1. Purpose

This document defines the panel-registry baseline of the platform.

It exists to preserve:
- stable panel identity
- readable operator-facing semantics
- continuity between panel meaning and dashboard structure
- a stable base for later renderer and workspace documentation

---

## 2. Registry Principle

A panel should not exist only because something is drawn on screen.

A panel should remain a registry-backed entity with:
- stable identity
- semantic role
- readable purpose
- bounded relationship to upstream meaning

---

## 3. Panel Registry Intent

The panel registry should help answer:
- what panel exists
- what it is for
- what family it belongs to
- what operator concern it serves
- what it must not silently redefine

---

## 4. Required Rule

Panel registry thinking should remain:
- explicit
- semantic
- stable
- non-authoritative over source truth
- consistent with dashboard baseline documentation

---

## 5. What Is Forbidden

The following remain forbidden:
- ad hoc panels with no stable identity
- panel meaning known only from visual habit
- registry-free panel growth
- presentation fragments silently treated as dashboard semantics

---

## 6. Final Rule

A mature dashboard system needs a readable panel registry, not only a pile of surfaces.

---

## 7. Status

This document is the active canonical panel-registry baseline until replaced by a stricter panel-registry reference.
