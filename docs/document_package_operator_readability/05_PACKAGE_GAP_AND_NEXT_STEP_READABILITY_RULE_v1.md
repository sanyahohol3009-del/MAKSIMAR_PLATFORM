# 05 PACKAGE GAP AND NEXT STEP READABILITY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for keeping package gaps and next actions readable to human operators
Rule: package open gaps and next steps must remain operator-readable so unfinished work is resumed deliberately instead of rediscovered through friction

---

## 1. Purpose

This document defines the package-gap-and-next-step-readability rule of the platform.

It exists to preserve:
- readable unfinished-work handling
- lower ambiguity around what remains next
- continuity between package closure and next action
- a stable base for later readability hardening

---

## 2. Gaps Principle

Package gap and next-step readability should remain understandable in terms of:
- what remains incomplete
- what should be done next
- what is blocked versus merely pending
- how readability preserves continuity

---

## 3. Required Rule

Package gap and next-step readability should remain:
- explicit
- selective
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- unfinished work rediscovered only by rereading
- next actions hidden in scattered notes
- gap meaning preserved only in operator memory
- package handling that hides what still remains

---

## 5. Final Rule

A mature documentation system keeps gaps and next steps readable before pauses turn pending work into drift.

---

## 6. Status

This document is the active canonical package-gap-and-next-step-readability rule until replaced by a stricter readability reference.
