# 05 NEXT DECISION POINT RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for preserving the next meaningful decision point across sessions and handoff points
Rule: the next decision point must remain readable so unfinished decision work can resume deliberately instead of being rediscovered after every pause

---

## 1. Purpose

This document defines the next-decision-point rule of the platform.

It exists to preserve:
- readable next-decision recovery
- lower ambiguity around what still requires judgment
- continuity between package closure and resumed decision flow
- a stable base for later reentry hardening

---

## 2. Next-Step Principle

Next decision point should remain understandable in terms of:
- what still remains undecided
- what kind of future decision is still expected
- what is blocked versus merely pending
- how next-decision recovery preserves continuity

---

## 3. Required Rule

Next decision point should remain:
- explicit
- selective
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- unfinished decision work rediscovered only by rereading
- next-decision context overloaded with weak or irrelevant details
- next-decision meaning preserved only in operator memory
- reentry that hides what still requires decision

---

## 5. Final Rule

A mature documentation system preserves the next decision point clearly before pauses turn pending judgment into drift.

---

## 6. Status

This document is the active canonical next-decision-point rule until replaced by a stricter reentry reference.
