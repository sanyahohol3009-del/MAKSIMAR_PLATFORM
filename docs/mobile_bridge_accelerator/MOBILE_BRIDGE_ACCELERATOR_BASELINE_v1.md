# MOBILE BRIDGE ACCELERATOR BASELINE v1

Status: active canonical mobile/bridge/accelerator baseline
Scope: whole-platform mobile bridge and accelerator orientation
Rule: the platform must preserve an explicit mobile/bridge/accelerator baseline so mobile extension logic remains modular, downstream, and non-legitimizing over core platform identity

---

## 1. Purpose

This document defines the current high-level mobile/bridge/accelerator baseline of MAKSIMAR/JARVIS.

It exists to preserve:
- mobile extension continuity
- bridge-based access discipline
- clear separation between app shell and compute backend
- explicit understanding of accelerator as extension rather than core legitimacy
- a stable foundation for later mobile and hardware-extension documentation

---

## 2. Baseline Principle

Mobile/bridge/accelerator logic is not merely “phone support.”

It also includes:
- how mobile interacts with the platform
- how bridge layers abstract backend differences
- how local and external compute modes remain unified at app level
- how accelerator logic remains optional extension, not foundational identity
- how fallback and degraded behavior preserve continuity

---

## 3. Core Mobile / Bridge / Accelerator Themes

The platform currently includes or plans for themes such as:

- mobile app shell as downstream access surface
- AI bridge as stable interaction boundary
- backend mode separation
- fallback and degraded behavior
- external accelerator attachment as optional capability extension
- thermal and operational constraint awareness
- unified operator/app experience across backend differences

---

## 4. Required Rule

No meaningful future platform expansion should contradict the need for explicit mobile/bridge/accelerator discipline.

If a feature makes optional extension behave like core legitimacy, the baseline wins.

---

## 5. What Is Forbidden

The following remain forbidden:
- mobile UI acting as backend authority
- accelerator extension acting as core legitimacy source
- backend differences leaking uncontrolled into app meaning
- mobile/bridge growth with no boundary discipline

---

## 6. Final Rule

Mobile/bridge/accelerator logic is not accessory fluff.
It is a structured extension layer of the platform.

---

## 7. Status

This document is the active canonical mobile/bridge/accelerator baseline until replaced by a stricter mobile integration reference.
