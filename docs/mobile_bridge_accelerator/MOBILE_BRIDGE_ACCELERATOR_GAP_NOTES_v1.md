# MOBILE BRIDGE ACCELERATOR GAP NOTES v1

Status: active canonical mobile/bridge/accelerator gap notes
Scope: limitations of the current mobile/bridge/accelerator baseline pass
Rule: the mobile/bridge/accelerator pass must remain explicit about what is still baseline-level or incomplete

---

## 1. Purpose

This document records the current limitations of the mobile/bridge/accelerator baseline pass.

It exists to keep the pass honest and bounded.

---

## 2. Current Gap Notes

### Gap 1
The current pass establishes a baseline, not yet a full app-shell, bridge-contract, or hardware-protocol family.

### Gap 2
The pass does not yet replace detailed discovery, handshake, thermal, or transport runbooks.

### Gap 3
Per-backend and per-device integration mappings are still future work.

### Gap 4
Future deeper documentation is still needed for:
- concrete bridge contract families
- discovery and handshake flow families
- thermal and power policy families
- transport and capability mapping
- tighter linkage to mobile app structure and future device roles

---

## 3. Required Rule

These notes do not invalidate the baseline.
They show where later hardening is still needed.

---

## 4. Final Rule

A mobile/bridge/accelerator baseline may begin high-level if its incompleteness is explicit.

---

## 5. Status

This document is the active canonical mobile/bridge/accelerator gap note set until replaced by a stricter mobile integration audit.
