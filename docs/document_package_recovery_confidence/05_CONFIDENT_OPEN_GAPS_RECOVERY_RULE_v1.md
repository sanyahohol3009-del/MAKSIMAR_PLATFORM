# 05 CONFIDENT OPEN GAPS RECOVERY RULE v1

Status: active_canonical
Document Type: canonical
Authority Level: operational
Interpretation Priority: high
Scope: rule for recovering open package gaps with readable confidence across sessions and handoff points
Rule: open package gaps must remain confidently recoverable so unfinished work can resume deliberately instead of being rediscovered through uncertain rereading

---

## 1. Purpose

This document defines the confident-open-gaps-recovery rule of the platform.

It exists to preserve:
- readable unfinished-work recovery
- lower ambiguity around what still remains
- continuity between package closure and next work
- a stable base for later confidence hardening

---

## 2. Gaps Principle

Confident open-gaps recovery should remain understandable in terms of:
- what remains incomplete
- what kind of future work is still expected
- what is blocked versus merely pending
- how gap confidence preserves continuity

---

## 3. Required Rule

Confident open-gaps recovery should remain:
- explicit
- selective
- meaningful
- readable
- non-bloated

---

## 4. What Is Forbidden

The following remain forbidden:
- unfinished work rediscovered only by rereading
- gap recovery overloaded with weak or irrelevant details
- open-gaps meaning preserved only in operator memory
- recovery that hides what still remains

---

## 5. Final Rule

A mature documentation system preserves open-gaps recovery with readable confidence before pauses turn pending work into drift.

---

## 6. Status

This document is the active canonical confident-open-gaps-recovery rule until replaced by a stricter confidence reference.
