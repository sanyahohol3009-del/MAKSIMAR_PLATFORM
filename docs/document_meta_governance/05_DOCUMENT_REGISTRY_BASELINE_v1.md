# 05 DOCUMENT REGISTRY BASELINE v1

Status: active_canonical
Document Type: canonical
Authority Level: constitutional
Interpretation Priority: strict
Scope: baseline rules for a central document registry
Rule: the documentation universe must become registry-backed so scale does not collapse discoverability and authority clarity

---

## 1. Purpose

This document defines the document-registry baseline of the platform.

It exists to preserve:
- one readable index of important documents
- machine-readable navigation across document families
- lower risk of duplication and drift
- a stable base for future JARVIS self-reading behavior

---

## 2. Registry Principle

A document registry should remain understandable in terms of:
- what document exists
- where it lives
- what type it is
- what authority level it carries
- what priority it should be read with
- what it depends on
- whether it is canonical, closure-oriented, or historical

---

## 3. Required Rule

The registry may start lightweight, but it should become the canonical navigation layer for new documentation families.

Initial coverage may begin with newly created packages rather than requiring full retroactive normalization at once.

---

## 4. What Is Forbidden

The following remain forbidden:
- letting document scale grow with no index
- relying only on folder memory for navigation
- leaving type and authority discoverable only by manual reading
- treating the registry as optional once documentation volume becomes large

---

## 5. Final Rule

A mature documentation system becomes registry-backed before it becomes unmanageable.

---

## 6. Status

This document is the active canonical document-registry baseline until replaced by a stricter registry standard.
