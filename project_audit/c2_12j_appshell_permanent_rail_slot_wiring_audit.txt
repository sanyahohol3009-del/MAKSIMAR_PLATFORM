C2.12j — AppShell permanent rail slot wiring audit

PURPOSE:
Audit the current AppShell/App.tsx structure before wiring the permanent dashboard navigation rail into the visible shell.

SCOPE:
No App.tsx modification yet.
No visual wiring yet.
No dashboard button hardcoding.
No drawer semantic regression.

CURRENT ACCEPTED MODEL:
- permanent left navigation rail = all dashboard groups / buttons
- center viewport = active dashboard visualization
- active dashboard left contextual drawer = functions / settings / tools for selected dashboard
- active dashboard right contextual drawer = state / diagnostics / context for selected dashboard
- top strip = network / weather / activity / notifications
- bottom strip = connected devices / users / robotic devices / environment
- top communication drawer = fullscreen ChatGPT-like JARVIS chat

AUDIT QUESTIONS:
1. Where is the current shell root?
2. Is App.tsx still too large?
3. Where is the current center viewport rendered?
4. Where are overlay drawers mounted?
5. Where is top communication drawer mounted?
6. Where should the permanent rail slot be inserted?
7. What must not be changed during first wiring?
8. Which existing files already expose permanent rail contracts?

EXPECTED DECISION:
The rail should be wired into a dedicated shell slot before the center viewport.
It must not be implemented as an overlay drawer.
It must not hardcode dashboard buttons.
It must consume the permanent rail integration boundary.
